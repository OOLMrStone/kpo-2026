# ДЗ 2. ПОС

Консольный модуль преподавательской оценки студентов. Поддерживает добавление студентов и критериев, выставление, исправление и отмену оценок, расчёт итогов и экспорт ведомости в CSV.

## Запуск

Нужна JDK 25. Команды выполняются из корня репозитория. При первой сборке Gradle скачает зависимости.

```bash
./gradlew :modules:homework-2:installDist --console=plain
modules/homework-2/build/install/homework-2/bin/homework-2
```

В Windows используется `gradlew.bat` и скрипт `homework-2.bat` из той же папки `bin`.

Демо использует обычное меню, домен и Spring-контейнер. Последний аргумент задаёт путь к новому файлу:

```bash
modules/homework-2/build/install/homework-2/bin/homework-2 --demo /tmp/pos-results.csv
```

Демо создаёт двух студентов, два критерия, выставляет оценки, показывает отказы, исправляет и отменяет оценку, восстанавливает её и экспортирует итог. Результат: Анна 8.40, Борис 8.20. Если CSV уже существует, выберите новое имя. Приложение не перезаписывает файлы.

По умолчанию отсутствующая оценка считается нулём. В строгом режиме итог доступен только после заполнения всех критериев:

```bash
modules/homework-2/build/install/homework-2/bin/homework-2 --strict
```

В меню показаны команды. Для исправления повторно выставьте оценку той же паре "студент, критерий". Для отмены есть отдельная команда. Идентификаторы вводятся вручную, пробелы по краям удаляются, регистр учитывается. Имена могут совпадать, коды внутри своего списка должны быть уникальны. Дроби принимаются с точкой и запятой. Ввод чисел ограничен девятью цифрами до разделителя и шестью после него, экспоненциальная запись не поддерживается.

Данные живут в памяти до завершения программы. CSV сохраняет итоги, но не является резервной копией ведомости. Восстановление из CSV и импорт не реализованы. Приложение работает последовательно, в одном потоке.

## Правила расчёта

В условии не определены шкала итога, обработка пропусков и округление. В работе приняты следующие правила:

- Максимум критерия и его вес строго положительны, балл находится между нулём и максимумом включительно.
- Веса относительные: 40 и 60 равнозначны 2 и 3. Сумма не обязана быть 1 или 100.
- Итог по шкале 0..10: `10 * sum(weight * score / maxScore) / sum(weight)`.
- Пропуск по умолчанию даёт нулевой вклад, но вес критерия остаётся в знаменателе. Рядом с итогом выводится число выставленных оценок.
- При `--strict` любой пропуск запрещает расчёт и экспорт всей ведомости. Нулевой балл считается выставленной оценкой.
- Для пустого рубрикатора итог не определён. Пустая ведомость без студентов экспортируется только с заголовком.
- Вычисления используют `BigDecimal`, деление на максимум выполняется с `DECIMAL128`. Итог округляется до сотых по `HALF_UP`.

Пример: домашняя работа 15/20 с весом 40 и экзамен 9/10 с весом 60 дают `10 * (40 * 15/20 + 60 * 9/10) / 100 = 8.40`.

Итог не хранится отдельно. После исправления, отмены оценки или добавления критерия он рассчитывается заново. Изменение и удаление студентов и критериев не входят в текущий набор сценариев, условие оставляет их необязательными. CRUD оценок реализован полностью.

## Карта DDD

| Понятие | Код и решение |
| --- | --- |
| Ubiquitous Language | `Student`, `Criterion`, `Rubric`, `Evaluation`, `Gradebook`, `FinalScore`: студент, критерий, рубрикатор, оценка, ведомость, итог. |
| Entity | `Student` определяется кодом `Id`, имя не влияет на равенство. `Gradebook` имеет постоянный идентификатор ведомости. |
| Value Object | `Id`, `Criterion`, `FinalScore` неизменяемы. `Criterion` представляет полную конфигурацию критерия; его равенство учитывает все поля. Его код служит ключом внутри рубрикатора. |
| Aggregate | `Gradebook` является корнем агрегата одного курса и владеет студентами, рубрикатором и оценками. Внешний код меняет их через методы корня. |
| Инварианты | `Criterion` проверяет максимум и вес. `Gradebook` проверяет уникальность кодов и принадлежность студента и критерия ведомости. `Evaluation` проверяет диапазон балла. |
| Repository | `GradebookRepository` является портом хранения агрегата. `InMemoryGradebookRepository` сохраняет и возвращает копии. |
| Domain Service | `FinalScoreService` объединяет оценки и рубрикатор, применяет правило пропусков и вычисляет итог. |

У `Evaluation` нет публичного конструктора. Создать оценку через API модели можно только методом `Gradebook.evaluate`, который находит настоящий критерий в рубрикаторе. Новый балл проверяется до замены старого. Поэтому неудачное исправление сохраняет прежнюю оценку.

Одна большая ведомость упрощает согласованность небольшого однопоточного приложения. При большом числе студентов и параллельной работе границу агрегата потребуется пересмотреть. Сейчас отдельные агрегаты и транзакции для каждой оценки усложнили бы учебную задачу.

## Архитектура Ports and Adapters

Все пути ниже относительны `src/main/java/studying/pos`.

```text
adapters/ConsoleApplication -> application/PosFacade -> domain
adapters/InMemoryGradebookRepository -> domain/GradebookRepository
adapters/CsvResultExporter -> application/ResultExporter
Main + ApplicationConfiguration -> сборка всех компонентов
```

- `domain`: модель, инварианты, расчёт, контракт репозитория. Зависит только от стандартной библиотеки Java.
- `application`: фасад сценариев, строки ведомости, порт экспорта и ошибка экспорта. Зависит от домена.
- `adapters`: консоль, хранилище в памяти и CSV. Зависит от внутренних слоёв.
- `ApplicationConfiguration`: composition root. Spring создаёт репозиторий, экспортёр, стратегию, доменный сервис и фасад. `Main` выбирает режим и подключает консоль.

Фасад загружает агрегат, вызывает предметный метод и сохраняет результат. Консоль разбирает ввод и выводит сообщения. CSV-адаптер выбирает кодировку и экранирование. Внутри домена нет Spring, консоли, путей или файлов. При экспорте сначала рассчитываются все строки, затем вызывается адаптер. Если строгий режим запрещает хотя бы один итог, файл не создаётся.

## Три паттерна GoF

| Группа | Паттерн | Задача и реализация |
| --- | --- | --- |
| Порождающий | Builder | `Rubric.Builder` постепенно собирает критерии, запрещает дубликаты и создаёт неизменяемый снимок. При добавлении критерия `toBuilder()` сохраняет старый рубрикатор до успешной сборки нового. |
| Структурный | Facade | `PosFacade` предоставляет консоли единый набор сценариев. Загрузка, изменение и сохранение ведомости, расчёт строк и вызов экспорта не размазаны по обработчикам меню. |
| Поведенческий | Strategy | `MissingScorePolicy` меняет правило пропусков без изменения формулы. `ZeroMissingScore` возвращает ноль, `RequireCompleteScores` запрещает неполный итог. Реальный выбор доступен через `--strict`. |

Сервис расчёта не проверяет конкретный класс стратегии. Builder, Facade и Strategy используются при обычном запуске, а не только в демонстрационных примерах.

## CSV

Кодировка UTF-8, разделитель запятая, столбцы: `student_id,name,score,evaluated,total`. Строковые поля заключены в кавычки; внутренние кавычки удвоены. Запятые и переводы строк сохраняются. Числа записываются с точкой. Каталог должен существовать, файл должен быть новым. При ошибке пути консоль сообщает об отказе и возвращается в меню.

## Проверки

```bash
./gradlew check --console=plain
```

Проверяет оба ДЗ и существующие практики. Для отдельного запуска: `./gradlew :modules:homework-2:check --console=plain`.

- `DomainTest`: диапазоны, дубликаты, неизменяемость, пропуски, формула, округление, исправление и отмена.
- `ApplicationTest`: сценарии фасада, снимки репозитория, сборка Spring и выбор стратегии.
- `AdapterTest`: сквозное демо, CSV, ошибки ввода и экспорта, обрыв команды без частичного сохранения.

Проверено: 25 тестов, покрытие строк 92.02%, ветвей 83.72%, Checkstyle без замечаний. Собранное приложение отдельно запущено в обоих режимах, итоговые CSV прочитаны независимым парсером. Проверен отказ экспорта неполной ведомости в строгом режиме.

Отчёты находятся в `build/reports/tests/test/index.html`, `build/reports/jacoco/test/html/index.html` и `build/reports/checkstyle/` внутри модуля. `check` требует минимум 80% покрытия строк и отсутствие замечаний Checkstyle.
